## Enterprise sizing

```
Base:        $60,000 / year   (up to 25 repos, up to 3 agents, 1 region)
+ Repos:     $1,000 / year per repo beyond 25
+ Agents:    $5,000 / year per agent beyond 3
+ Compliance: $20,000 / year per custom framework (HIPAA, FedRAMP, ISO 27001)
+ Regions:   $10,000 / year per additional region
```

**Example**: 60 repos, 5 agents, HIPAA compliance in us-east-1 only.
`$60,000 + 35 × $1,000 + 2 × $5,000 + 1 × $20,000 = $125,000 / year`

## What is not counted against your subscription

- Reads to the API (`GET` endpoints) — separate 100 rpm limit per API key
- Dashboard usage
- Failed webhook validations
- Cached-verdict returns (same `base_sha + head_sha + policy_hash` within 15 minutes)

## FAQ

<AccordionGroup>
  <Accordion title="Is the OSS engine really free forever?">
    Yes. The Apache-2.0 licensed local engine will always be free. We may add a Business Source License to specific hosted-only features later, but the local `trikon verify` command stays permissive.
  </Accordion>
  <Accordion title="Do you charge per developer?">
    No. Repos, not seats. Trikon is a governance product, not a dev tool. Priced per-repo because value scales with agent activity per repo, not headcount.
  </Accordion>
  <Accordion title="What counts as one repo?">
    One git repository under a single owner/name in your Git host. Monorepos count as one repo, but require a per-service `.trikon/policy.yaml` for meaningful policy separation.
  </Accordion>
  <Accordion title="Can I switch tiers mid-month?">
    Yes. Upgrades are pro-rated on the same day. Downgrades take effect at the next billing cycle.
  </Accordion>
  <Accordion title="Can I try Team before paying?">
    14-day free trial, no card required. Design-partner slots (weekly feedback + product input) get 50% off year one — talk to sales.
  </Accordion>
  <Accordion title="What if I hit the 5-minute execution cap?">
    You get a `require_human` verdict with a note that the cap was hit. If it happens often, upgrade to Enterprise for unlimited execution.
  </Accordion>
</AccordionGroup>
